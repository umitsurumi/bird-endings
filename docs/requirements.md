# 鸟类转生测试需求文档

## 1. 项目概述

本项目是一个轻量级趣味测试。用户完成 12 道单选题后，系统根据用户在多个隐藏维度上的得分和隐藏彩蛋规则，返回一种最终结局。

测试包含：

* 18 种常规鸟类结局
* 1 种隐藏彩蛋结局：鸽子
* 1 种时间随机隐藏结局：KFC
* 12 道单选题
* 6 个隐藏维度
* 1 个独立鸽子彩蛋分
* 基于归一化维度与加权距离的匹配算法
* 结果清晰度反馈机制

结果页展示对应结局文案。结局文案以第 18 节的 18 + 1 种鸟类结局 + 1 种隐藏结局为准。

## 5. KFC 时间随机隐藏结局机制

### 5.1 触发条件

KFC 结局只在北京时间的星期四触发，时间范围为星期四 00:00:00 到 23:59:59。

当用户完成全部 12 道题并点击“查看结果”时，系统在提交动作中执行一次 KFC 触发判断：

```text
if 当前北京时间是星期四 and random() < 0.05:
    result = KFC
else:
    继续执行鸽子彩蛋判断和常规鸟类匹配
```

### 5.2 触发优先级

KFC 触发优先级最高：

```text
KFC > 鸽子 > 常规鸟类结果
```

如果 KFC 触发，即使用户同时满足鸽子彩蛋条件，最终结果也必须返回 KFC。

### 5.3 概率口径

KFC 在北京时间星期四当天的触发概率为 5%。由于只在一周中的星期四生效，如果用户提交时间在一周内均匀分布，整体平均触发率约为：

```text
1 / 7 * 5% ≈ 0.71%
```

因此 5% 不应理解为全量用户长期触发率，而应理解为“星期四提交用户”的条件触发率。

### 5.4 随机结果持久化

KFC 随机判断必须只在提交结果时执行一次。提交完成后，最终结果应保存为本地结果记录。

用户刷新页面或重新打开页面时，系统必须读取已保存的最终结果，不得重新执行 KFC 随机判断。否则用户可以通过反复刷新页面刷出 KFC 结局。

重新开始测试并再次提交时，可以重新执行一次 KFC 判断。

### 5.5 结果类型

为避免把 KFC 当作鸟类结果处理，最终结果建议使用显式类型字段：

```text
result_kind = "regular" | "pigeon" | "kfc"
```

其中：

* `regular` 表示 18 种常规鸟类结果
* `pigeon` 表示鸽子彩蛋结果
* `kfc` 表示 KFC 时间随机隐藏结局

## 6. 鸽子彩蛋机制

### 6.1 鸽子分来源

| 题目 | 选项 | 鸽子分 |
| ---- | ---- | ------ |
| Q4   | B    | P +1   |
| Q7   | C    | P +1   |
| Q12  | D    | P +2   |

### 6.2 鸽子触发规则

采用“双层触发”。

```text
if P_total >= 3:
    result = 鸽子
else if P_total == 2 and 常规匹配清晰度较低：
    result = 鸽子
else:
    进入常规鸟类匹配
```

### 6.3 常规匹配清晰度较低的判定

常规匹配完成后，得到：

```text
best_distance = 最接近鸟类的距离
second_distance = 第二接近鸟类的距离
distance_gap = second_distance - best_distance
```

当满足以下任一条件时，视为常规匹配清晰度较低：

```text
distance_gap <= 1.0
```

或：

```text
best_distance >= 6.0
```

因此鸽子完整判断为：

```text
if P_total >= 3:
    result = 鸽子
else:
    先计算常规鸟类匹配结果
    if P_total == 2 and (distance_gap <= 1.0 or best_distance >= 6.0):
        result = 鸽子
    else:
        result = 常规鸟类结果
```

### 6.4 鸽子触发目标

鸽子作为隐藏彩蛋结果，目标出现率约为 3% - 5%。
该比例通过后续测试数据调整。

## 8. 用户维度归一化

用户答题后得到 6 个原始维度总分：

```text
S_total
M_total
E_total
A_total
O_total
X_total
```

由于各维度在题目中的理论最大值和最小值不同，使用每个维度自己的范围归一化到 -2 到 2。

### 8.1 当前题库理论分数范围

| 维度 | 理论最小值 | 理论最大值 |
| ---- | ---------: | ---------: |
| S    |         -2 |         15 |
| M    |         -1 |          9 |
| E    |         -9 |         15 |
| A    |         -4 |          7 |
| O    |        -10 |         14 |
| X    |        -14 |         19 |

### 8.2 归一化公式

```text
norm = round(((raw - min_value) / (max_value - min_value)) * 4 - 2)
```

归一化后进行边界截断：

```text
norm = clamp(norm, -2, 2)
```

示例：

```text
S_norm = clamp(round(((S_total - S_min) / (S_max - S_min)) * 4 - 2), -2, 2)
```

归一化后的用户画像为：

```text
{
  "S": S_norm,
  "M": M_norm,
  "E": E_norm,
  "A": A_norm,
  "O": O_norm,
  "X": X_norm
}
```

## 9. 加权距离匹配算法

### 9.1 维度权重

| 维度       | 权重 |
| ---------- | ---: |
| S 安定欲   |  1.0 |
| M 迁移欲   |  1.2 |
| E 表达欲   |  1.0 |
| A 攻击性   |  1.2 |
| O 秩序感   |  1.0 |
| X 意义焦虑 |  1.0 |

M 和 A 权重略高，用于增强迁徙型鸟类与攻击型鸟类的识别度。

### 9.2 距离公式

对每只鸟计算用户画像与鸟类画像之间的加权曼哈顿距离。

```text
distance =
1.0 * |S_user - S_bird|
+ 1.2 * |M_user - M_bird|
+ 1.0 * |E_user - E_bird|
+ 1.2 * |A_user - A_bird|
+ 1.0 * |O_user - O_bird|
+ 1.0 * |X_user - X_bird|
```

距离越小，表示越接近该鸟类画像。

### 9.3 常规结果计算

```text
1. 计算用户 6 个维度原始分
2. 将原始分归一化为 -2 到 2
3. 对 18 只常规鸟类分别计算加权距离
4. 取距离最小的鸟作为常规候选结果
5. 记录 best_distance、second_distance、distance_gap
6. KFC 未触发时，结合鸽子规则决定最终结果
```

## 10. 平票处理规则

当多只鸟距离相同，按以下顺序处理。

### 10.1 第一优先：画像独特性

为每只鸟预先计算“画像独特性分”。

画像独特性分定义为：

```text
uniqueness(bird) = 该鸟与其他 17 只鸟的平均加权距离
```

当多个鸟类距离相同，优先选择画像独特性分更高者。

### 10.2 第二优先：固定兜底优先级

若画像独特性分也相同，使用固定优先级。

建议兜底优先级：

## 11. 结果清晰度反馈

结果页可根据常规匹配的清晰度，展示不同强度的结果表达。清晰度反馈只适用于 18 种常规鸟类结果，不适用于鸽子和 KFC。

### 11.1 清晰度计算

```text
distance_gap = second_distance - best_distance
```

### 11.2 清晰度分档

| 条件                                            | 清晰度 |
| ----------------------------------------------- | ------ |
| distance_gap >= 1.5 且 best_distance < 6.0      | 高     |
| 1.0 < distance_gap < 1.5 且 best_distance < 6.0 | 中     |
| distance_gap <= 1.0 或 best_distance >= 6.0     | 低     |

### 11.3 展示规则

高：

```text
你的结果非常明确：你转生成了……
```

中：

```text
你的结果偏向……，但也带有一些其他鸟类的影子。
```

低：

```text
你的特质跨在几种鸟之间，但最终你转生成了……
```

若常规鸟类结果需要展示第二接近结果，可使用：

```text
你身上还藏着「第二接近鸟类」的影子。
```

鸽子和 KFC 不展示第二接近鸟类提示。KFC 是时间随机隐藏结局，不是基于维度距离匹配出的鸟类结果，因此不得展示“你身上还藏着……的影子”。

```python
RANGES = {
    "S": {"min": -2, "max": 15},
    "M": {"min": -1, "max": 9},
    "E": {"min": -9, "max": 15},
    "A": {"min": -4, "max": 7},
    "O": {"min": -10, "max": 14},
    "X": {"min": -14, "max": 19},
}

WEIGHTS = {
    "S": 1.0,
    "M": 1.2,
    "E": 1.0,
    "A": 1.2,
    "O": 1.0,
    "X": 1.0,
}

def clamp(value, min_value, max_value):
    return max(min_value, min(value, max_value))

def normalize_score(dim, raw):
    min_value = RANGES[dim]["min"]
    max_value = RANGES[dim]["max"]
    norm = round(((raw - min_value) / (max_value - min_value)) * 4 - 2)
    return clamp(norm, -2, 2)

def weighted_distance(user_profile, bird_profile):
    distance = 0
    for dim in ["S", "M", "E", "A", "O", "X"]:
        distance += WEIGHTS[dim] * abs(user_profile[dim] - bird_profile[dim])
    return distance

def calculate_uniqueness(bird_name):
    target = BIRD_PROFILES[bird_name]
    distances = []
    for other_name, other_profile in BIRD_PROFILES.items():
        if other_name == bird_name:
            continue
        distances.append(weighted_distance(target, other_profile))
    return sum(distances) / len(distances)

def is_beijing_thursday(submitted_at):
    # submitted_at 应转换为北京时间后判断 weekday
    # weekday == 3 表示星期四，具体取值以实现语言为准
    return submitted_at.astimezone("Asia/Shanghai").weekday() == 3

def should_trigger_kfc(submitted_at, random_value):
    return is_beijing_thursday(submitted_at) and random_value < 0.05

def get_result(raw_scores, p_total, submitted_at, random_value):
    # KFC 隐藏结局优先级最高，只在提交时随机判断一次
    if should_trigger_kfc(submitted_at, random_value):
        return {
            "result": "KFC",
            "result_kind": "kfc",
            "is_easter_egg": True,
        }

    user_profile = {}
    for dim in ["S", "M", "E", "A", "O", "X"]:
        user_profile[dim] = normalize_score(dim, raw_scores[dim])

    distances = {}
    for bird, profile in BIRD_PROFILES.items():
        distances[bird] = weighted_distance(user_profile, profile)

    sorted_results = sorted(distances.items(), key=lambda item: item[1])

    best_bird = sorted_results[0][0]
    best_distance = sorted_results[0][1]
    second_bird = sorted_results[1][0]
    second_distance = sorted_results[1][1]
    distance_gap = second_distance - best_distance

    # 距离完全相同的候选
    candidates = [
        bird for bird, distance in distances.items()
        if distance == best_distance
    ]

    if len(candidates) > 1:
        candidates.sort(
            key=lambda bird: calculate_uniqueness(bird),
            reverse=True
        )
        best_bird = candidates[0]

    # 鸽子彩蛋优先判断
    if p_total >= 3:
        return {
            "result": "鸽子",
            "result_kind": "pigeon",
            "is_easter_egg": True,
            "best_regular_result": best_bird,
            "second_regular_result": second_bird,
            "best_distance": best_distance,
            "second_distance": second_distance,
            "distance_gap": distance_gap,
        }

    if p_total == 2 and (distance_gap <= 1.0 or best_distance >= 6.0):
        return {
            "result": "鸽子",
            "result_kind": "pigeon",
            "is_easter_egg": True,
            "best_regular_result": best_bird,
            "second_regular_result": second_bird,
            "best_distance": best_distance,
            "second_distance": second_distance,
            "distance_gap": distance_gap,
        }

    if distance_gap >= 1.5 and best_distance < 6.0:
        clarity = "high"
    elif distance_gap > 1.0 and best_distance < 6.0:
        clarity = "medium"
    else:
        clarity = "low"

    return {
        "result": best_bird,
        "result_kind": "regular",
        "is_easter_egg": False,
        "second_regular_result": second_bird,
        "best_distance": best_distance,
        "second_distance": second_distance,
        "distance_gap": distance_gap,
        "clarity": clarity,
    }
```

## 14. 用户流程

1. 用户进入测试首页
2. 点击开始测试
3. 依次完成 12 道单选题
4. 系统计算 S、M、E、A、O、X 六个原始维度分
5. 系统计算 P 鸽子彩蛋分
6. 系统判断当前提交时间是否为北京时间星期四，并执行一次 KFC 随机触发判断
7. 若 KFC 触发，系统直接返回 KFC 结局
8. 若 KFC 未触发，系统归一化用户六维画像
9. 系统计算用户画像与 18 只常规鸟类画像的加权距离
10. 系统得到最接近鸟类、第二接近鸟类、结果清晰度
11. 系统根据 P 分与清晰度判断是否触发鸽子
12. 系统返回最终结局
13. 用户查看结果页
14. 用户可分享结果页或结果图

### 14.1 答题交互补充

1. 用户在题目页可返回上一题。
2. 返回上一题时，页面必须恢复用户刚才已选择的选项。
3. 当前题目未选择任何选项时，“下一题”按钮不可用，用户无法进入下一题。
4. 第 12 题未选择任何选项时，“查看结果”按钮不可用，用户无法提交。
5. 在用户完成全部 12 道题并点击“查看结果”前，系统只将答题进度和选项临时保存到 `localStorage`。
6. 临时保存内容至少包含当前题号、每题已选选项、最后更新时间。
7. 用户刷新页面或重新打开页面时，如果存在未提交的 `localStorage` 草稿，应恢复到上次答题位置，并恢复所有已选选项。
8. 提交动作只在 12 道题全部选择完成后发生。提交时统一读取本地暂存答案，计算原始分，并执行一次 KFC 随机触发判断。
9. 若 KFC 未触发，再计算归一化画像、常规匹配结果、鸽子彩蛋判断和最终结果。
10. 提交完成后，可将最终计算结果保存为本地结果记录；重新开始测试时必须清除草稿和结果记录。
11. 用户刷新页面或重新打开页面时，如果存在已提交的本地结果记录，应直接展示该结果，不得重新执行 KFC 随机判断。

### 14.2 单页 HTML 原型要求

1. 原型文件放置在 `docs/` 目录下。
2. 原型为单页面 HTML 文件，不依赖构建流程。
3. 如使用 Tailwind CSS、图标库或其他组件库，统一通过 CDN 链接引入。
4. 布局采用移动端优先的响应式设计，在手机、平板和桌面宽度下都应保持可读、可点选、无内容重叠。
